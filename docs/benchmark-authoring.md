# Benchmark integrity
Local metadata schema: parsed metadata.json fields id/title/version/base_revision/resources plus task.toml equivalent for human/tool interoperability. Not advertised as Harbor-compatible.
Materialize pinned Git base plus bug patch. Golden is minimal patch relative to buggy snapshot. Candidate submissions replace only source/migrations; host runner never imports candidate. Freeze source before execution; no reference/test/solution mounts in candidate containers. Dependencies remain in stripped image, original source removed. Each run has internal network, fresh PG cluster, two API processes, shared scheduling-only volume and separate external verifier.
Verifier directly checks DB aggregates and real HTTP outcomes, randomized UUIDs/amounts, 100 cross-process retries, terminal rejection, BOLA, strict amounts, crash boundaries and 20 synchronized race rounds for RL-01. Exact response equality required by published API, no code-string checks. Alternate optimistic CAS and lock-only solutions have explicit validation gates.
Version 1.0.2 synchronizes request start before candidate transactions. At the unsafe-read checkpoint it allows a peer blocked on a PostgreSQL lock to proceed, so correct locking solutions may retain instrumentation and actor serialization. Baseline stale reads still rendezvous before updates. Keep these accepted solutions when changing scheduling; never require a particular patch text to pass.
Validation checks baseline/no-op/partial/hardcoded/canned/disabled/suppressed/deleted-evidence/unit-only failures and golden pass over five clean seeds. Results distinguish FAIL from ENVIRONMENT_ERROR, TIMEOUT, VERIFIER_ERROR. Public sources/solutions are portfolio-public; truly unseen evaluation requires private verifier bundle/network policy.
Only trusted host orchestrator touches Docker. Candidate migrations get disposable owner privileges before private fixtures; candidate API has runtime role only. Docker kernel isolation is not a claim of safety against kernel exploits.
